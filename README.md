# 称呼管理器 (Appellation Manager)

SillyTavern 浏览器扩展。解决一件事：**让角色说话时的称呼保持一致**。

主路径是**先建立小说的称呼**：导入小说正文，让模型把「谁喊谁什么」抽出来，
整理成一张称呼表存起来，跟当前开着哪个聊天无关；以后哪个聊天要用再拿过去。
也可以手工填，或从聊天记录里反向扫描。

管的三类关系：

| 关系 | 例子 |
| --- | --- |
| 角色 → 用户 | 白鹭管你叫「陆哥」 |
| 用户 → 角色 | 你管白鹭叫「白鹭姐」 |
| 角色 → 角色 | 白鹭管星野叫「小星星」（群聊） |

每条关系带**别名**（陆哥 / 哥 / 小陆哥）和**关系阶段**（初见、熟悉、亲密、决裂……）。
登记之后，扩展把整张表压成一段提示词注入给模型。

## 它不做什么

- 不改你已经存下来的聊天记录。历史消息永远是原文。
- 不做文本替换式的「全局改名」。称呼只影响**送进模型的提示词**和扩展面板里的显示。
- 不往角色卡、世界书里写东西。
- 提取时不会把模型编出来的称呼当事实——每条结果都带**原文证据**给你核。

## 安装

**方式一：让酒馆自己拉（推荐）**

酒馆 → 扩展 → **Install extension** → 粘贴仓库地址：

```
https://github.com/hhdsz0807/st-appellation-manager
```

装完刷新页面。

**方式二：手动放目录**

扩展目录：`<SillyTavern>/public/scripts/extensions/third-party/st-appellation-manager/`

把 `manifest.json` / `index.js` / `core.js` / `extract.js` / `ui.js` / `style.css` 复制进去，刷新酒馆页面。

装好后在「扩展」抽屉里能看到 **称呼管理器** 面板。如果没出现，按 F12 看控制台有没有
`[称呼管理器]` 开头的报错。

## 用法 A：先建立小说的称呼（推荐主路径）

**这条路径跟当前开着哪个聊天无关。** 先把小说里的称呼建立起来，存成一部「小说」，
以后哪个聊天要用再拿过去。面板最上面是「小说称呼库」。

1. 点 **新建** 给这部小说起个名（写书名就行）。也可以直接粘正文开跑——会自动建一部。
2. 把小说正文粘进文本框，点 **导入小说原文（txt / md）**，**或者直接把 txt 文件拖进那个框**。
   > - **编码不用管**：GBK / GB18030 / Big5 / UTF-16 的老小说都能读，扩展按 BOM → 严格 UTF-8 →
   >   GB18030 → Big5 的顺序自动试，并在状态栏告诉你最后用的是哪种。读完还会报一下中文比例，
   >   万一认错了（满屏乱码）会提示你。
   > - 正文只留在浏览器内存里，不写进盘（几百 KB 的文本塞进设置会让每次存档都变慢）。
   >   刷新页面要重新导入，但**提取出来的称呼表是持久化的**。正文按小说分开存，切小说不会互相冲掉。
   > - 小说原文**不要**用 JSON——JSON 是本扩展自己导出的称呼表格式（见下面「导出/导入」）。
3. 选模型：
   - **酒馆当前连接（推荐）**——就是你已经在酒馆里配好的那个模型，包括自定义 OpenAI 兼容端点。
     不用填密钥，也不受浏览器跨域限制。
   - **自定义 OpenAI 兼容端点**——扩展自己直连一个端点，要填地址、模型名、API Key。
     ⚠️ 需要那个端点带 CORS 头，否则浏览器会拦下请求。API Key 是**明文存在酒馆设置里**的。
4. 设分块：每块字数（默认 1500）、最多几块（默认 12）、从第几个字开始。
   下面会实时算出「**要发几次请求、处理第几到第几字**」——先看清代价再点。
5. 点 **开始提取**。会弹确认框告诉你请求次数。过程中可以 **中止**。
6. 跑完，「称呼表」区出现整理好的结果：**同一对关系的多个称呼，命中多的当主称呼，其余自动变别名**。
   每一行还有命中块数、置信度，底下可以展开看**原文证据**核对模型有没有编。
7. 用起来：
   - **复制表格** → 得到 Markdown 表格，直接粘进世界书或角色卡。
   - **导出称呼表 JSON** → 备份或分享给别人（是扩展自己的格式，跟小说原文无关）。
   - **把这张表一起注入提示词** → 聊天时让模型知道原著里人物之间怎么称呼（人名级，不需要聊天里有这个人）。
   - **把这个称呼表用到当前聊天**（可选，展开）→ 见下面。

长篇可以分几次跑：每轮结束后记住「下次从第几个字接着」，把它填回「从第几个字开始」。

### 把小说的称呼表用到当前聊天（可选）

小说里的名字和聊天里的角色不一定对得上，所以这一步做一次**映射**：

1. 展开「把这个称呼表用到当前聊天」。
2. **同名会自动对上**，你只需要改错的那些。小说里的「我/你/他」**不会自动映射**——
   那多半是主角本人，不是你。要指到你身上就手动选。
3. 点 **写进当前聊天的称呼表**：写进本聊天的关系表。原来手填的关系会被同键覆盖，其余保留。
   映射不上的名字直接跳过，不猜。
4. 或者点 **存为全局默认库**：不依赖映射，换个聊天也能用。

映射是**每聊天各自记的**——同一部小说用到不同聊天，映射互不影响。

## 看关系：放射图

「称呼关系」默认就是**放射图**，不用再一行行读表格：

- 上面选一个**圆心**（默认是当前正在说话的角色），其他人放射状摆在周围。
- 每条辐条标两个方向：`→ 圆心这样叫对方`、`← 对方这样叫圆心`——所以双向称呼一眼能对上。
- 外围角色之间如果也有称呼，会额外画一条往外鼓的弧线（角色超过 5 个就不画，并如实告诉你有几条没画）。
- **点任何一个角色名，就把它换成圆心**——沿关系网走着看很方便。
- 没登记称呼的方向不显示标签，辐条画成虚线。
- 右上角可以切到「表格」精确编辑；小说称呼表也有同一套图。

图形坐标是 0–100 的百分比、容器撑成正方形，所以不会被面板宽度拉变形。

## 用法 B：手工填 / 从聊天记录扫描

1. 打开一张角色卡或一个群聊 → 「称呼关系」区域（默认放射图；切到「表格」可以精确编辑）。
2. 表格里每一行是一个方向的关系（`白鹭 → 小陆`），填**称呼**、别名、阶段、备注。输入框失焦即保存。
3. 点 **扫描候选称呼**：读最近 40 楼消息，找出「他叫她小星星」这类句子里的称呼。
   点 **采纳**（旧称呼自动降级成别名，不会丢）。
4. 点 **一致性检查**：哪些登记的称呼在最近聊天里从没出现过、哪些实际用法和登记值不一样。
5. 「提示词注入」保持开启，位置默认「对话内、深度 4」。想让模型更严格遵守就改到「主提示内」。

## 提示词注入说明

开关打开且当前聊天至少有两个参与者时，会注入类似这样的一段：

```
【称呼表】以下为已确认的称呼，请在对话中自然使用，不要复述本表。
白鹭 → 小陆：陆哥（别名：哥、小陆哥；关系：熟悉）
小陆 → 白鹭：白鹭姐
（未列出的关系按原本的名字称呼。称呼会随关系阶段变化时，以关系更贴合的写法为准。）
```

| 选项 | 作用 |
| --- | --- |
| 注入位置 | `主提示内` / `对话内（按深度）` / `主提示前` |
| 深度 | 只在「对话内」时生效 |
| 消息角色 | 这段内容以 system / user / assistant 的身份出现 |
| 范围 | 全部关系 / 只含与用户相关 / 只含当前角色相关 |
| 带别名·阶段·备注 | 控制每行括号里的内容 |
| 带表头说明·兜底规则 | 控制首行和末行 |
| 长度上限 | 超长时逐条截断，并在正文里写明「另有 N 条未列出」 |

## 宏

写在世界书、角色卡、快捷回复里，生成时自动替换：

| 宏 | 结果 |
| --- | --- |
| `{{call::白鹭::用户}}` | 白鹭对你的称呼；没登记时回退成目标的名字 |
| `{{callAlias::用户::白鹭}}` | 别名列表，顿号分隔；没有则空 |
| `{{callTable}}` | 当前聊天的整张称呼表（单行压缩） |

源和目标都能写：角色名、「用户」、`user`。支持前缀匹配（写「白」匹配「白鹭」，唯一时）。
宏名必须是 ASCII——酒馆的宏语法只认 `[a-zA-Z][\w-_]*`，中文宏名注册不上。

## 斜杠命令

```
/appellation list
/appellation set from=白鹭 to=用户 call=陆哥
/appellation del from=白鹭 to=用户
```

中文别名 `/称呼` 会在宿主机允许时一起注册。

## 数据存在哪

| 数据 | 位置 | 说明 |
| --- | --- | --- |
| **小说库（含称呼表）** | `extension_settings["st-appellation-manager"].novels` | 全局的，跟聊天无关；这是「先建立小说的称呼」的落点 |
| 本聊天的称呼 | `chat_metadata["st-appellation-manager"].relations` | 跟着聊天文件走，导出聊天会带上 |
| 小说名 → 聊天角色的映射 | `chat_metadata["st-appellation-manager"].novelMapping[小说id]` | 每聊天各自记，同一部小说用在不同聊天互不影响 |
| 正文本身 | 只在内存里 | 刷新页面即失效，需要重新粘贴（称呼表本身是持久化的） |
| 全局默认库 | `extension_settings["st-appellation-manager"].library` | 本聊天没登记的称呼回退到它 |
| 注入选项 / 提取选项 | `extension_settings["st-appellation-manager"].inject` / `.extract` | 全局生效 |
| 看法偏好（图/表）、端点模型列表 | `extension_settings["st-appellation-manager"].ui` / `.extract.custom` | 纯界面偏好 |

导出有三条路：**导出称呼表 JSON**（单部小说 + 整理好的表，扩展自己的格式，用来备份或分享给别人）、
**复制表格**（Markdown，适合粘进世界书）、以及面板「操作」里的 **导出 JSON**
（本聊天关系 + 小说库 + 全局库 + 选项，整包备份）。导入都认。

小说**原文**不走 JSON：用「导入小说原文（txt / md）」或直接拖 txt 文件进来。

- 复制表格用的 `navigator.clipboard` 在你的浏览器/非 HTTPS 环境下是否被拦。

以上任意一项没过，都不要当它已经能用。

## 开发

```
core.js      纯逻辑，无宿主依赖，可直接在 Node 里 import
extract.js   模型调用（酒馆连接 / 自定义端点）+ 提取编排，可注入假 fetch
ui.js        只画界面，所有读写都通过 index.js 传进来的 api
index.js     唯一的宿主接线层（上下文、元数据、注入、宏、命令、面板）
```

改完跑 `npm test`（= 两个测试文件）。动了 `index.js` / `ui.js` 再跑
